# Meeting-Monster 悬浮窗快捷操作与转写状态设计

日期：2026-08-07

## 目标

在不改变“用户手动开始转写”这一产品机制的前提下，简化 Chat 输入区，把录音转写控制和清空聊天集中到 `•••` 菜单，同时补齐适合 Meeting-Monster 的键盘操作和胶囊状态反馈。

本次设计解决以下问题：

1. 胶囊最右侧方块按钮语义不直观。
2. Chat 输入区同时放置录音、清空和 AI 操作，信息密度过高。
3. 转写只有“就绪/正在实时转写”两种提示，启动、停止和异常过程不够明确。
4. Electron 网页类快捷键在桌面悬浮工具中没有实际价值，且可能造成误刷新。
5. Cluely 的持续监听机制不适用于 Meeting-Monster，不能直接照搬“Ask Cluely”和“Stop session”。

## 核心产品原则

- Meeting-Monster 继续采用手动录音转写：打开胶囊或 Chat 不会自动访问麦克风或系统音频。
- 菜单中的“实时转写”开关是录音转写的唯一显式开关；胶囊负责展示状态，不在菜单里重复状态文案。
- 清空聊天与录音转写互不影响。清空只删除已有内容，不擅自停止音频采集。
- 只添加对当前工作流有价值的快捷键，不照搬 Cluely 的 Ask 或 Stop session。
- 常用文本编辑快捷键必须保留，设置页输入配置时不能受到录音快捷键干扰。

## 胶囊设计

### 退出按钮

- 最右侧方块改为红色 `×`。
- 保持当前行为：点击后彻底退出 Meeting-Monster，而不是隐藏窗口或仅停止转写。
- 使用危险操作语义色，但避免大面积纯红背景；默认采用深色半透明底、红色图标，悬停时增强红色边框和背景。
- 保留明确的 `aria-label="退出 Meeting-Monster"` 和提示文本。

### 五状态提示

胶囊状态文本区域使用固定宽度，状态切换时不得改变胶囊整体尺寸。

| 状态 | 胶囊反馈 | 含义 |
| --- | --- | --- |
| `idle` | 绿色圆点＋“就绪” | 可以开始转写 |
| `connecting` | 橙色呼吸圆环＋“正在启动” | 正在连接音频来源和识别模型 |
| `recording` | 红色动态声波＋“正在转写” | 录音和实时转写正在运行 |
| `stopping` | 橙色渐隐圆点＋“正在停止” | 正在停止采集并释放资源 |
| `error` | 红色警告符号＋“转写异常” | 启动、音频或识别过程失败 |

异常的完整错误信息继续显示在展开的 Chat 面板中；胶囊只显示短状态，避免撑宽或遮挡桌面。

动效遵循 `prefers-reduced-motion`。用户要求减少动效时，呼吸、声波和渐隐改为对应状态的静态图形。

## `•••` 菜单设计

菜单保持现有深色、紧凑的悬浮样式，按“窗口操作—会话内容—隐私与设置”分组。

```text
快捷操作
  显示/隐藏窗口              Ctrl+\
  移动悬浮窗                 Ctrl+方向键
  滚动聊天                   Ctrl+Shift+↑/↓
────────────────────────────
  实时转写             Ctrl+S   [开关]
  清空聊天             Ctrl+R
────────────────────────────
  截图保护                       [开关]
  设置                              ›
```

### 实时转写

- 固定显示“实时转写”，右侧使用一个开关表示开/关，不再切换“开始转写/停止转写”两套文字。
- 开关关闭时点击：开始录音转写。
- 开关开启时点击：停止录音转写。
- `connecting` 和 `stopping` 期间开关进入过渡状态并暂时不可重复点击，防止快速操作产生并发启动或停止。
- 状态详情由胶囊五状态提示承担，菜单中不增加第二个红点或“正在转写”文案。

### 清空聊天

- 清空转写记录、当前 AI 回答和相关聊天状态。
- 如果存在进行中的 AI 请求，先取消该请求，防止清空后旧回答重新写回。
- 不停止正在进行的录音转写；清空后产生的新转写内容可以继续出现。
- 不清除模型连接配置、音频来源、截图保护或其他设置。

### 删除的入口

- 不添加“Ask / 唤出提问”菜单项或快捷键。
- 不添加“Stop session”菜单项或 `Ctrl+Shift+\`。Meeting-Monster 不会随悬浮助手自动监听，停止能力由“实时转写”开关统一承担。

## Chat 输入区简化

从输入框下方移除：

- 开始转写
- 停止
- 清空

保留：

- Assist
- 追问
- 重述
- 已选择段数
- 发送提示和发送按钮

转写错误仍可在 Chat 面板中显示。用户不需要打开菜单才能看到失败原因。

## 快捷键及作用范围

| 快捷键 | 作用 | 范围 |
| --- | --- | --- |
| `Ctrl+\` | 显示/隐藏 Meeting-Monster | 全局 |
| `Ctrl+方向键` | 移动悬浮窗 | 全局 |
| `Ctrl+Shift+↑/↓` | 滚动 Chat 内容 | 全局 |
| `Ctrl+S` | 切换开始/停止实时转写 | 仅胶囊或 Chat 面板聚焦时 |
| `Ctrl+R` | 清空聊天 | 仅 Chat 面板聚焦时 |

设置 BrowserWindow 聚焦时，`Ctrl+S` 不得启动或停止转写，避免用户编辑模型连接信息时误触。

移动悬浮窗时复用现有屏幕边界约束，不能把胶囊移出可用工作区。滚动快捷键只滚动聊天/回答内容，不滚动背景网页或设置窗口。

## Electron 网页快捷键策略

在 Meeting-Monster 的 BrowserWindow 中拦截无关的浏览器和调试快捷键：

- 刷新和强制刷新：`F5`、`Ctrl+R` 的原生刷新行为、`Ctrl+Shift+R`
- 开发者工具：`F12`、`Ctrl+Shift+I`
- 查看源码：`Ctrl+U`
- 打印：`Ctrl+P`
- 网页查找：`Ctrl+F`
- 网页缩放：`Ctrl++`、`Ctrl+-`、`Ctrl+0`
- 网页全屏：`F11`
- 网页保存：`Ctrl+S` 的原生保存行为

其中 `Ctrl+S` 和 `Ctrl+R` 在允许的 Meeting-Monster 窗口中由自定义动作接管，其余窗口只阻止原生网页行为。

以下编辑能力必须保留：

- `Ctrl+C/V/X/A`
- `Ctrl+Z/Y`
- 方向键、退格、删除、Tab
- 输入区现有提交行为

不拦截操作系统级 `Alt+F4`。

## 状态与命令边界

当前录音器由 Chat renderer 持有，主进程不能只调用 ASR stop 就声称录音已经结束。快捷键和菜单必须走同一套 renderer 录音命令，使以下资源同步切换：

1. `PcmAudioRecorder` 的麦克风/系统音频轨道。
2. 主进程 ASR 会话。
3. Chat 面板的录音阶段。
4. 胶囊订阅的公开 ASR 状态。
5. 菜单开关的可用和选中状态。

建议把开始、停止、切换、清空提取为可复用的 Chat 会话命令，由按钮、菜单与本地快捷键调用同一入口，避免出现三套行为。

## 错误与边界情况

- 模型或音频来源未就绪：开关保持关闭，显示错误；不得进入伪录音状态。
- 启动中再次触发 `Ctrl+S`：忽略，直到启动成功或失败。
- 停止中再次触发 `Ctrl+S`：忽略，直到资源释放完成。
- 输入设备意外结束：切换为 `error`，关闭菜单开关，并释放剩余资源。
- 清空时正在生成 AI 回答：取消请求后再清空，迟到的响应不得回填。
- 清空时正在录音：保持录音，清空后的新转写作为新内容继续写入。
- 全局快捷键注册失败：应用继续运行，并在可诊断日志中记录失败组合键；不把菜单状态伪装成快捷键可用。

## 可访问性

- 菜单使用正确的 `menu`、`menuitem` 或开关语义。
- “实时转写”开关暴露 `aria-checked`，过渡阶段暴露禁用状态。
- 状态变化通过简短的可访问文本表达，不依赖颜色或动画传达唯一信息。
- 红色 `×` 具有明确名称，不使用单独的视觉字符作为唯一语义。
- 键盘焦点样式保持可见，菜单关闭后焦点返回 `•••` 按钮。

## 测试与验收

实施采用 TDD：先加入失败测试，再修改生产代码。

自动化验证至少覆盖：

- Chat 输入区不再渲染开始、停止和清空按钮。
- 菜单渲染“实时转写”开关与“清空聊天”，不渲染 Ask 或 Stop session。
- 菜单开关能够开始和停止同一录音器，过渡阶段不能重复操作。
- 清空聊天取消 AI 请求并清除内容，但不调用停止录音。
- `Ctrl+S` 仅在胶囊/Chat 聚焦时切换转写；设置窗口中不触发。
- `Ctrl+R` 在 Chat 中清空且不会刷新页面，其他 Meeting-Monster 窗口不执行原生刷新。
- `Ctrl+\`、移动和滚动快捷键分发到正确窗口。
- 浏览器/调试类快捷键被阻止，复制、粘贴、撤销等编辑快捷键仍可使用。
- 五种 ASR 状态均映射到正确的中文文案与样式钩子。
- 红色 `×` 仍调用彻底退出应用的现有命令。
- TypeScript 类型检查、renderer 单元测试、desktop 结构测试和构建通过。

手工验收至少覆盖：

- 在浅色、深色和复杂桌面背景中，五种状态都能辨认且胶囊宽度不跳动。
- 使用菜单与 `Ctrl+S` 开始/停止时，麦克风或系统音频资源确实释放。
- 打开设置页编辑输入框时，复制粘贴正常且 `Ctrl+S` 不会误启动录音。
- 使用方向键移动时不会把悬浮窗移出当前显示器可用范围。
- 回答区滚动快捷键不移动整个窗口，不影响背景应用。

## 不在本次范围

- 不自动开始录音或持续监听。
- 不新增 Ask 快捷键或唤出提问功能。
- 不提供用户自定义快捷键设置页。
- 不修改远程模型、ASR 模型或音频来源配置。
- 不改变截图保护的底层实现。
- 不构建或发布安装包，除非用户在实施完成后另行要求。
